# Design system

Tokens, the Tailwind bridge, the patterns every control follows, and the component inventory. Behavior lives in docs/UX-SPEC.md; this file is how things look and are built.

## Token layers

1. **Semantic tokens** are what components use. They describe a role, never a color: `--ink` is "the text color", whatever a theme makes it.
2. **Themes** assign values to semantic tokens in `apps/web/src/styles/themes/<id>.css`. A theme is nothing but a token set plus, later, an optional decoration stylesheet.
3. **Derived tokens** are computed once in the bridge from semantic tokens (the nested corner radii). They follow every theme automatically.
4. **Component tokens** exist only when a component needs its own knob. None yet. Prefer a semantic token.

Raw values (a hex color, a pixel radius, a literal duration) never appear inside a component, and `pnpm lint` enforces it (see "Token guard"). If a design needs something the tokens cannot express, add a token, document it here, and define it in every theme. The theme contract test fails until every theme has it.

## Semantic tokens

| Token                                             | Role                                                                                                                  |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `--canvas`                                        | Page background                                                                                                       |
| `--surface`                                       | Cards, fields, panels                                                                                                 |
| `--surface-raised`                                | Hover states and anything sitting on a surface; visibly different from `--surface`                                    |
| `--ink`                                           | Primary text                                                                                                          |
| `--ink-muted`                                     | Secondary text, labels, hints. Still body-text contrast (4.5:1)                                                       |
| `--accent`                                        | The one brand color: active edges, primary buttons, links                                                             |
| `--on-accent`                                     | Text and icons placed on `--accent`                                                                                   |
| `--accent-soft`                                   | Tinted backgrounds: selected rows, chips                                                                              |
| `--line`                                          | Dividers and decorative borders: list headers, the toolbar rule, keycaps, cards                                       |
| `--edge`                                          | A control's resting edge: fields, secondary buttons, the table's card. 3:1 or more against `--canvas` and `--surface` |
| `--focus`                                         | Focus ring. Often equals `--accent`; dark themes may pick a brighter hue                                              |
| `--danger`, `--success`                           | Error and success text and indicators (the out-of-range message, the copy check)                                      |
| `--art-1`, `--art-2`, `--art-3`                   | The theme art's colors (`ThemeArt`). Decoration only, so they have no contrast pair                                   |
| `--type-display`, `--type-body`, `--type-numeric` | Font stacks for headings, running text, and numbers                                                                   |
| `--shape-sm`, `--shape-md`, `--shape-lg`          | Border radii                                                                                                          |
| `--elevation-sm`, `--elevation-md`                | Shadows (or glows, in neo-noir)                                                                                       |
| `--motion-fast`, `--motion-base`, `--motion-slow` | Durations. Zeroed under `prefers-reduced-motion` (see "Motion")                                                       |
| `--motion-ease`                                   | The theme's easing curve                                                                                              |
| `--highlight-fade`                                | How long a highlight takes to fade (1200 ms). A fade of color with no movement, so reduced motion keeps it            |
| `--motion-glide`                                  | The even curve for something travelling a distance (a unit gliding to its place), where `--motion-ease` front-loads   |

The full list is the single source of truth in `apps/web/src/lib/themes.ts` (`TOKEN_CONTRACT`), with the contrast pairs every theme must pass (`CONTRAST_PAIRS`).

## Tailwind bridge

`apps/web/src/styles/global.css` maps tokens into Tailwind's theme with `@theme inline`, so utilities keep the `var()` reference and re-theme at runtime:

| Utility                                                                       | Resolves to                                                                                 |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `bg-canvas`, `bg-surface`, `bg-surface-raised`, `bg-accent`, `bg-accent-soft` | color tokens                                                                                |
| `text-ink`, `text-ink-muted`, `text-on-accent`, `text-danger`, `text-success` | color tokens                                                                                |
| `fill-art-1`, `stroke-art-2` (and the rest of the art set)                    | art tokens, for the theme art's SVG                                                         |
| `border-edge`, `border-line`, `border-accent`, `outline-focus`                | color tokens                                                                                |
| `font-display`, `font-body`, `font-numeric`                                   | type tokens; `font-numeric` also turns on tabular digits                                    |
| `rounded-sm`, `rounded-md`, `rounded-lg`                                      | shape tokens                                                                                |
| `rounded-nested`, `rounded-nested-md`                                         | derived: the shell's corner minus its border and inset (see "Corners")                      |
| `shadow-sm`, `shadow-md`                                                      | elevation tokens                                                                            |
| `duration-fast`, `duration-base`, `duration-slow`, `ease-standard`            | motion tokens; every `transition-*` utility already defaults to fast and the theme's easing |

Custom utilities, also in `global.css`:

| Utility                   | Use                                                                                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `focus-ring-within-inset` | Draws the focus ring inside a wrapper whose descendant has focus, for a control flush against an edge that clips (the theme menu's radio labels)                                      |
| `focus-ring-inset`        | Draws a control's own focus ring inside its edge, for a control flush in a filled row or a menu's gutter (Units' handles), where the base ring's 2 px offset would spill past the row |

Layout and spacing use Tailwind's default scale (`p-4`, `gap-2`, `max-w-2xl`). Those are not themed.

## Token guard

`pnpm lint` checks every string in `apps/web/src`, which is where class lists live, and fails on a value that bypasses the tokens. The patterns are in `eslint.config.js` (`RAW_VALUES`). A new pattern is written without "/" (a selector's regex ends at the first one) and tried on a scratch file of violations and allowed look-alikes before it is trusted.

| Flagged                                                                                  | Use instead                                                                       |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Raw colors: hex, `rgb()`, `hsl()`, `oklch()`, `color-mix()`                              | A color token: `bg-surface`, `text-ink`, `border-line`                            |
| Tailwind palette colors: `bg-red-500`, `text-white`                                      | A color token. The palette does not follow the theme                              |
| Arbitrary values holding a length, color, time, or variable: `w-[37px]`, `bg-(--accent)` | The token utility, or the spacing scale                                           |
| Numbered durations and stock easings: `duration-150`, `ease-in-out`                      | `duration-fast`, `duration-base`, `duration-slow`, `ease-standard`                |
| Radii, shadows, and fonts outside the tokens: `rounded-xl`, `shadow-lg`, `font-mono`     | `rounded-sm/md/lg`, `rounded-nested`, `shadow-sm/md`, `font-display/body/numeric` |
| A number of milliseconds in `setTimeout` or `setInterval`                                | A named constant in `src/lib/timing.ts`                                           |

Allowed: arbitrary values that name structure rather than a value (`transition-[border-color,box-shadow]`, `grid-cols-[1fr_auto_1fr]`), the spacing scale, and `var(--token)` where the gallery paints its swatches. Raw values belong in the theme files and the bridge, which are CSS and outside the guard.

**When it flags something.** Use the existing token if one fits. If none does, the need is a design decision: bring it to the owner with a recommendation (reuse a token, or add one to every theme) before building on it. Never silence the guard with a disable comment.

## Component rules

Every component in `apps/web/src/components/`:

1. Uses tokens only: no hex, rgb, px radii, or literal durations, and no arbitrary-value utilities where a token utility exists (`duration-fast`, not `duration-[var(--motion-fast)]`).
2. Is keyboard-operable with a visible focus indicator (see "Focus"). A browser test tabs through the page and fails on any stop without one.
3. Has an accessible name: visible label, `aria-label`, or `aria-labelledby`.
4. Has a touch target of at least 44 × 44 CSS px (`min-h-11`, `size-11`, `w-11`), per WCAG 2.5.8 best practice.
5. Works at 320 px wide and 400 % zoom without horizontal scrolling. Anything added to a row that shares space (the header, the toolbar) is checked at 320 px before it is done, and at small sizes it gives way (a word that becomes screen-reader-only, a row that stacks) rather than shrinking targets. Form controls in a narrow column take `w-full min-w-0`, and code shown on a page wraps (`whitespace-pre-wrap wrap-break-word`) rather than scrolls.
6. Respects reduced motion by using the motion tokens.
7. Appears in `/dev/gallery` in the variants and states that ship, so every theme can be checked against it.
8. Passes the Playwright axe suite on desktop and mobile.
9. Takes what it branches on as a prop, never as children: Astro hands a TSX component its children as rendered markup (`<Keycap label="Mod" />`).
10. Writes ARIA roles, handlers, and `aria-*` attributes out on the element, never through a spread, so jsx-a11y can check them. A jsx-a11y rule that does not fit a sound pattern (click-only rows under `aria-activedescendant`) is disabled on that element alone, with the reason; the token guard is never disabled.
11. Gives a labelled container a role that takes a name (`role="group"`): `aria-label` on a plain `div` names nothing.
12. If it owns keys, moves focus into itself when it opens, onto the control Enter should press, returns focus to its trigger when it closes, and answers its keys only while focus is inside (WCAG 2.1.4), as the calculator does.
13. Sets no margin on its own outer edge: whoever places it spaces it (`TableLayout`'s `TABLE_ROWS_CELL` and `TABLE_CALCULATOR_CELL`), so the same component sits right in any layout and in the gallery. A divider's own spacing is part of what it is (`ToolbarDivider`).

Prefer native elements when they are good enough (`<button>`, radios, `<dialog>`). The converter's box is the one hand-built composite control, on the WAI-ARIA combobox pattern (ADR 0006), its popup the table's place, a grid or a listbox (ADR 0012). A new composite starts from that pattern and the axe suite, and brings in a library only for a measured need recorded in an ADR.

## Patterns

### Recipes

A class list more than one file builds from is a recipe in `src/lib/recipes.ts`, written once so a shared shape cannot drift between Astro and TSX: the cards (`CARD`, and `LIST_CARD` for the table's place), a panel's title (`PANEL_TITLE`), a side panel's accent edge while it has the keys (`PANEL_ACTIVE`), the fluid shells (`SHELL`, `SHELL_BORDERED`, `SHELL_GHOST`, `SHELL_PANEL`), the menus (`MENU_ROOT`, `MENU_SIZER`, `MENU_SIZER_LABEL`, `MENU_SHELL`, `MENU_TRIGGER`, `MENU_CHEVRON`, `MENU_OPTION`, shared by the theme menu and the category menu), a setting's row (`OPTION_ROW`, which `Switch` builds on; a menu's choice shares its shape), the fill of a row holding a control, under the pointer and with focus (`CHOICE_FILL`), a checkbox (`CHECKBOX`), a unit's symbol wherever it shows (`unitSymbol()`), the short message for a value with no answer (`NO_ANSWER`), the field row (`FIELD_ROW`), the rows a field's cursor moves through (`CURSOR_ROW`, and `rowFill()` for their fill), the type ladders (`NUMBER_SIZES`, `WORDMARK_SIZES`), and the wordmark's face and lines (`WORDMARK_FACE`, `PLAYING_LINE`, `ART_LINE`).

- A recipe whose look depends on a state is a small function returning class lists (`rowFill(selected, current)`, `unitSymbol(alone)`), so the states can never both apply and fight over one property.

- A list only one file uses stays in that file, as an UPPER_SNAKE constant beside its markup (`TEXT_LAYER` in ValueField, `DISPLAY_TEXT` in Calculator). It moves to `recipes.ts` when a second file needs it.
- A recipe holds only what every use shares. A part one use needs and another must not have goes in that use or in a variant recipe: merging the shells once gave the shortcuts map a fading edge (docs/LEARNINGS.md, "Merging recipes can undo a fix").
- TSX joins class lists with `cx()`, which leaves out any a condition turned off (`cx('font-semibold', !compact && 'text-ink-muted')`); Astro joins them with `class:list`. Never a template string with `? '' :`, which leaves stray spaces.
- Recipes hold tokens only, like every class list, and the token guard checks them.

### Edges and borders

- **2 px is a control's edge.** Fields, secondary buttons, and the table's place (`LIST_CARD`, the box's popup, whose rows people pick) share `border-2` in `--edge`, so no control looks lighter-edged than its neighbor (the table's since Sean, 2026-10-08). A border is the one edge children cannot paint over; an inset ring is drawn under them, which is how row highlights once ate into it.
- **1 px is a divider or a keycap.** The line under a menu's trigger, between the matches' groups, the toolbar divider (`border-l`), and keycaps use `border`. A card is 1 px in `--line` (the calculator, the lab's panels), a light frame for what comes and goes.
- **Open is accent.** A shell's edge is `border-edge` at rest and `border-accent` while open or while something inside has focus; a ghost menu, with no edge at rest, draws its open edge as a 2 px outline inside its card (`MENU_SHELL`), which takes no room. The calculator's card does the same while focus is inside it: its 1 px border and a 1 px ring turn accent, 2 px like a focused box, so nothing moves.
- **A control's edge identifies it.** `--edge` passes 3:1 against the page and the surface in every theme, so a field's resting edge meets WCAG 1.4.11 by itself, and the theme test enforces it. `--line` stays subtle because a divider only groups. Each theme's `--edge` is its `--line` moved toward `--ink` to the first step past 3:1. Introduced 2026-10-06 as a trial the owner may roll back (findings-0, sixth pass).

### Focus

- **One ring.** The base layer gives every `:focus-visible` element a 2 px `--focus` outline offset by 2 px. Buttons, chips, and links rely on it and add nothing.
- **Never pair `outline-none` with focus utilities.** In Tailwind v4, `outline-none` sets the outline style to none, and `focus-visible:outline-2` then draws nothing (docs/LEARNINGS.md).
- **Inset where an edge clips or crowds.** `focus-ring-within-inset` on the menus' option labels; `focus-ring-inset` on a control flush in a filled row (Units' handles), so the ring follows the control's corners inside its row (Sean, 2026-10-15). Joined pieces (segments, the Move menu) take focus on their own edge instead (`SegmentedControl`).
- **Shell edges for fields and open shells.** The field's input sets `outline-none`; its shell's accent edge (`focus-within:border-accent`) is the indicator. The shortcuts toggle shows the ring while closed and none while open (`group-data-open:outline-none`): the open shell's accent edge says where focus is. The menus' triggers show the standard ring, nothing clipping them at rest; while open, focus is in their list.
- **A tap never moves focus into a text field.** On a touch screen that brings the keyboard up, so a control that puts the caret back in the box after a click or a key leaves focus where it is after a tap (`pressedByTouch()`, `src/lib/modality.ts`; ADR 0015). A control that closes on `pointerup` (the category menu's choices) ends the tap with `preventDefault()` on `touchend`, or the browser's click after it lands on what the control uncovered.
- **The list is never focused.** Rows are virtually focused through `aria-activedescendant`; the listbox has `tabIndex={-1}` so Chrome does not make it a Tab stop.

### Motion

- **The wordmark at play** is the one animation driven by script: frames come from `requestAnimationFrame` only while the heading (the name and its art) is hovered or a tap plays it, its pace comes from the pointer's speed, and it never starts under `prefers-reduced-motion`. Every other motion is a CSS transition on the motion tokens.
- **Type that steps to fit.** Text that may not fit its box steps down a type ladder (sizes, largest first, in `src/lib/recipes.ts`) and takes the largest size at which it fits: never a size in between, and never clipped. Two mechanisms measure it, one per kind of box. `useFitStep` (`src/lib/fit-step.ts`) fits text in an island that clips its own box, re-measured on every render and on resize: the calculator's display on `NUMBER_SIZES`. `useFieldFit`, beside it, fits a field's whole row in one pass and a fixed order: the chip's name gives way first, then the number steps down `NUMBER_SIZES`. `fitPhrase` (`src/lib/wordmark-motion.ts`) fits a line laid over a fixed room, once per phrase: the wordmark on `WORDMARK_SIZES` through `fitSteps()`, which may also set two lines with `leading-tight` (`text-sm` and `text-base` keep two lines within the name's height, or nearly). A transform squeezes only a phrase too long at every step, which the wordmark lab flags and a browser test rejects. New text that must fit uses one of the two with a ladder, never a third way; a column that may not fit gives way whole through `useColumnsFit` instead (see "Columns that give way"). All three measure again when their box resizes and when the theme changes, since a theme's fonts change what fits.
- **Nothing clips a moving line.** Before its line leaves the flow, the wordmark holds its box at the name's size, width and height, and releases it when the line settles home, so nothing beside it moves. It never clips the box, so descenders and tall symbols show whole; each frame fits by construction instead (a flipping letter is never wider than the room its phrase leaves).

- Components write `transition-colors` (or `transition-[border-color,box-shadow]`, `transition-transform`) and nothing else: the bridge makes every transition default to `--motion-fast` and `--motion-ease`.
- Buttons, chips, and shell edges fade; list rows and theme options change instantly, so keyboard movement never lags.
- **A check that draws itself in** (`check-draw`, `global.css`) confirms an action done in a button with a label, such as Settings' resets and the calculator's send (Sean, 2026-10-10): `CheckIcon` in the success color after the label, its stroke drawn over `--motion-slow`. It rests fully drawn and animates from hidden, so reduced motion, which stops every animation, shows it whole. An icon-only button confirms by swapping its icon for `CopiedIcon` instead ("Icon buttons and the toolbar").
- **A unit moving between shown and hidden glides and flashes** (Sean, 2026-10-15). In one length, three beats: what leaves fades out in its first 30 %, before anything slides over where it was; what moves glides throughout; what arrives fades in over the second half, once what moved out of its place has gone, so nothing lingers as a ghost the rows slide through. The glide (`features/converter/glide.ts`) measures where each part of the table sits on the page (never the screen, so a page that scrolls as the table changes moves nothing), renders the change at once, and slides each part that moved from where it was (a unit keeps its key in its row or its line in Hidden, so it travels between them), fading in what is new and fading out a copy of what left where it was, over `--motion-slow` on `--motion-glide`; the card clips what slides in from outside it. A theme's `--motion-ease` suits a fade or a shell opening, not travel: it does most of its movement in the first fifth, and a glide on it reads as a jump (Sean, 2026-10-15). It moves the rows themselves, not pictures of them, so the page takes clicks throughout (docs/LEARNINGS.md, "A view transition takes no clicks"). The flash (`lib/flash.ts`) is the accent's soft tint, held for a fifth of `--highlight-fade`, then fading back to the element's own fill on `--motion-glide`: on a row or a Hidden line that arrives, and on Hidden when units go into it.
- Reduced motion zeroes the motion tokens with an unlayered rule placed after the theme imports (a layered rule loses to the themes' unlayered token blocks), and a blanket `!important` rule stops any other transition or animation. A browser test checks the tokens read `0ms` in every theme. `--highlight-fade` is not zeroed: a highlight is a change of color, no movement, and it keeps telling where a unit went (it runs as a script animation, which the blanket rule does not stop).

### Corners

An element inset inside a rounded shell uses the shell's radius minus the inset, border included, so the curves stay concentric; an inner corner as round as the outer one looks swollen.

- `rounded-nested`: inside a field or its list (`lg` shell, 2 px border, 8 px inset). The chip, the copy button (`Button nested`), and list rows.
- `rounded-nested-md`: inside a menu (`md` shell, 2 px border, 4 px gutter). The theme menu's options.

### Responsive layout

- **Decide by the box, not the layout.** Whether something fits is decided by measuring its own box (a field's number and chip, `useFieldFit`) or by its container's size (the header's menus, the start's tiles), never by which layout it is in, a breakpoint standing in for its width, or a count of characters, so one component reads right in a wide box and on a phone. Where the converter places its pieces lives in one place, as named class lists (`TABLE_GRID` and its cells in `TableLayout.tsx`), never inside a component.
- **Tiles by their container.** The start shows the categories two across, and four once the table's place, an `@container`, is 512 px wide (`@lg:grid-cols-4`): the smallest stock container size above the widest case, Theorem's "Temperature", which needs a container of 456 px. A browser test pins both sides in every theme, and the field's arrows read how many tiles sit in a row from the layout, never from a count.
- **A column beside the rows.** The converter from `md` is a grid of two columns and four rows, `auto auto auto 1fr`: the toolbar, the box, and the table (across the last two rows) in the first column, and the side panel open (the calculator, Units, or Display) in the second, spanning the box's row through the last (`TABLE_SIDE_CELL`, `self-start`), its top level with the box's (Sean, 2026-10-15). An item that spans a `1fr` track sizes only that track, so a panel taller than the box and the table adds its height under the table, never between the box and the table (docs/LEARNINGS.md). Until 2026-10-15 the calculator's card was a subgrid of the first three rows, its title row on the toolbar's line and its display level with the box.
- **Ahead of a row of tools.** A control that leads a row of icon buttons (the category menu before the converter's tools) sits at the row's left and the tools at its right end while both fit; where they do not, the tools keep the line and the control wraps onto one of its own under them, both flush left. The control comes first in the markup, and `flex-wrap-reverse` with `justify-between` (`TABLE_TOOLS_ROW` in `TableLayout`) stacks a wrapped row's first line at the bottom and puts a line's one item at its start. The browser's own fit decides, in every theme, with no breakpoint to measure; a browser test pins both sides, and the toolbar's arrows follow what shows (ADR 0014). Introduced 2026-10-08 as a trial in its own commit, the control first at the row's end, then moved to its start the same day, as the more logical order of controls; kept for now (Sean, 2026-10-08). The tools had drifted to the right end on their own line too (an `ml-auto`); both lines are flush left again (Sean, 2026-10-15).
- **Switch at a container size, measured.** CSS cannot see a row wrap, so a row that must change layout when it no longer fits switches at the smallest stock container size above its widest case, not at a one-off breakpoint. The page header is an `@container`, and its menus switch at `@max-sm:`, 384 px of header, where Hardhat's name, the widest, needs 351 (452 while the layout switch stood beside the theme menu, ADR 0013). Browser tests pin both sides of the switch in every theme.
- **Columns across rows of buttons.** A list whose rows are buttons with a separate button beside each (the table's rows and their copy buttons), is one grid, each row and its main button spanning it with `grid-cols-subgrid`, so names, values, and symbols line up in columns while no control sits inside another.
- **Columns that give way.** A grid column that is good to have but not needed to read a row (the table's names, beside the symbols) keeps its cells to one line, clipped, and marks them `data-column`; `useColumnsFit` (`src/lib/fit-step.ts`) shows it while every one of its cells fits whole and hides it in every row at once otherwise, so rows never wrap, clip, or differ from each other. More such columns join it in the order they give way. A column may have stand-ins, cells marked `data-instead` with its name, which show exactly where it hides: Both's fraction moves under the decimal, on a second line in the value's columns (Sean, 2026-10-15). What the column holds stays for screen readers in a copy of its own. Introduced 2026-10-08 (Sean: names wrapped beside long values on an iPhone 13).
- **As wide as the widest label.** A control whose label changes while it is used (the theme and category menus) takes its width from an unseen sizer in flow (`invisible grid h-0`) that stacks every label in one cell (`col-start-1 row-start-1`) with the control's padding (and border, where it has one), so it never jumps between labels.

### Fluid shells

A control that opens a list or panel keeps both in one shape, drawn over the page so nothing reflows. Its native semantics stay inside the shell (the theme menu is a `fieldset` of radios), because a native popup such as a `<select>`'s list is drawn by the OS, where no token reaches. Its recipes live in `src/lib/recipes.ts` and every instance builds from them:

- A **placeholder** with `group relative` and a fixed size holds the layout: `h-12` for the theme and category menus (the category menu as wide as its widest label, through an unseen sizer, open or closed: its counts are bare numbers, in the room its chevron takes), `size-12` for the shortcuts map. It carries `data-open` while open.
- The **shell** inside takes `SHELL` (2 px edge, `overflow-hidden`, and the open state: `z-20`, accent edge, `shadow-md`; no motion, since a shared part must not decide how a variant moves), one resting style, and its own position and radius.
  - `SHELL_BORDERED`: bordered at rest, `bg-surface`, accent on `focus-within`, and its edge eases between edge and accent, because the shell stays in view through the change. Fields (`rounded-lg`, plus `shadow-sm` at rest); the theme and category menus took it too (`rounded-md`) until the trial below.
  - `SHELL_GHOST`: a borderless icon button at rest that becomes a card when open. Nothing eases: its panel appears and vanishes at once, so its edge must too, or a fading accent square is left around the icon. A browser test checks the ghost edge cannot animate. The shortcuts map (`rounded-md`), anchored with `absolute top-0 right-0` so it grows left and takes its width from its panel. The theme and category menus take a ghost shell of their own (Sean, 2026-10-08), `MENU_SHELL`, so they compete less with the box and the table: nothing at rest, so the trigger (`MENU_TRIGGER`) is all there is, as wide as the menu, which is as wide as its widest label, with a ghost button's tint, corners, and focus ring, 44 px tall like the icon buttons, 12 px from each edge to the label and the chevron, open or closed. Open, the shell becomes the card around the trigger and its list, the same size; its accent edge is a 2 px outline drawn inside the card's edge, which, like a border, nothing inside can paint over and, unlike one, takes no room, so nothing moves when it appears.
- A **menu** inside a shell is a trigger (`MENU_TRIGGER`: 44 px, the value and its chevron, `MENU_CHEVRON`, after the theme menu's muted label "Theme" from `sm`; the category menu shows its value alone, or its own name, "Category", muted before a choice, as a field shows its placeholder) over a `fieldset` of radios in `SHELL_PANEL`, each a label (`MENU_OPTION`: 44 px, `rounded-nested-md`, the checked one in the accent's soft fill, focus ringed inside). Open, a trigger that shows its value alone (the category menu; the theme menu below `sm`) reads its label instead, muted, heading the list as the shortcuts map's title heads its panel, the checked choice's fill marking the value; introduced and kept 2026-10-08. The theme menu and the category menu build from the same three.
- The list or panel renders inside the shell, in flow, under a `border-t` divider (`SHELL_PANEL` for a header menu's panel, which shows only while open). `overflow-hidden` clips it to the corners; the shell's own border is never clipped.

### Fields

The converter's box is `ValueField`, placed by `TableLayout`: it takes a shell's edge (`SHELL`, `SHELL_BORDERED`, `rounded-lg`, plus `shadow-sm`) without ever opening, its list being the table under it.

- **Row.** `FIELD_ROW` (`src/lib/recipes.ts`): 60 px tall inside the 2 px border, `pl-4 pr-2 gap-2`. The 44 px chip and trailing button keep the same 8 px from the top, bottom, and right edges, and the value starts 16 px in.
- **Text layer.** The value is drawn by an `aria-hidden` layer over an input whose own text is transparent (`text-transparent caret-ink selection:bg-accent-soft`). The input keeps the caret, selection, focus, mobile keyboards, and the accessibility tree; the layer gets the typography, which is how the exponent marker in `1.5E21` is `font-semibold` (core's parser reports where it is). The layer matches the input's font, size, and line box, follows its horizontal scroll, and is `pointer-events-none`.
- **Size steps.** `useFieldFit` (`src/lib/fit-step.ts`) picks the largest of the five `NUMBER_SIZES` (`text-2xl sm:text-3xl` down to `text-base`) at which the layer's text fits on one line, measured before paint on every render and whenever the row resizes (see "Type that steps to fit").
- **Chip.** Symbol, then plural, on one baseline (`items-baseline`). Its name gives way before the field's text steps down a size: the same measurement tries the row with the name, then without it (hidden, not removed, so it can be measured), so the name stays while the box has room, whatever the box's width.
- **Buttons inside a field** (the chip's two, copy) are out of the Tab order, because the field's own keys do the same jobs.
- **Category menu** at the left of the toolbar row over the box, its left edge on the box's, or on a line of its own under the tools, flush left, where the row has no room (see "Ahead of a row of tools"). It shows the category's name alone, as wide as the widest, so the row keeps it beside the tools as long as it can.

### Lists

- Rows sit in a `p-2` gutter, each `rounded-nested px-2`, so a highlight sits inside the edge with the same 8 px as the chip and the row text starts 16 px in, under the value.
- **Matched letters** are set heavier and nothing else changes: names `font-semibold`, category names `font-bold`, a symbol's matched part `text-ink`. The span comes from core's `matchSpan`.
- **The cursor's lists** (the table's units, the matches, and the start's tiles): cards (`LIST_CARD`) with the same `p-2` gutter, each row `CURSOR_ROW` (`min-h-11 cursor-pointer rounded-nested px-2`). Their fill comes from `rowFill()`: the unit in the box in `bg-accent-soft`, the chip's color; the row the cursor is on, or the pointer is over, in `bg-surface-raised`, the muted tint of a hovered row, never an outline. The accent fill marks the selection, so the cursor takes the quieter tint. No transition, so keyboard movement never lags.
- **No value yet** is an em dash (`NO_VALUE` in the converter's state) in `text-ink-muted`, read as "no value" by screen readers, with an empty 44 px place where the copy button would be when copy buttons are on, so the columns never shift.
- **Sections** in the table: a header row in `PANEL_TITLE` (`px-2 pb-1`), a `border-line` rule over every section after the first; a section's checkbox in Edit and the Hidden list sits on its heading, its units' checkboxes set in `pl-6` under it, as a tree's children. A sizer row (`invisible h-0`, the rows' `px-2`) holds every value under every rounding, every symbol, and every name, so each column is as wide as the widest it could hold and nothing moves as what shows changes (docs/LEARNINGS.md, "A subgrid's padding counts toward its parent's edge columns"). Edit lists the shown units in Hidden's lines (checkbox, symbol, name, no values) and keeps the table's foot and Hidden where they are (shown units above, hidden ones below, Sean 2026-10-15): its button reads Done in place, switched on (`on`), the card's edge the accent while focus is in it, the card's controls taking a panel's keys (`lib/panel-keys.ts`), and while editing the foot sticks to the screen's bottom edge (`sticky bottom-0 bg-surface`), as wide as the rows it covers, with no corners of its own for them to show through.
- **Values line up on the decimal point**: a decimal in two subgrid columns, its whole part right-aligned and the rest from its decimal mark left-aligned after it, in equal-width digits (`font-numeric`); a value written whole (a fraction, a dash, a message) spans both, right-aligned. The drawn parts are hidden from screen readers, who hear the value whole from an `sr-only` copy, as they do a symbol (docs/LEARNINGS.md, "Decimal points line up in two columns, not with padding").
- **Matches** read "symbol name", both left-aligned (`grid-cols-[auto_minmax(0,1fr)] gap-x-3`), the symbol in `unitSymbol()`, matched letters heavier through `MatchedText`. Each category's group has a header, `text-xs font-medium text-ink-muted` with the name in ink and the count beside it, and a `border-line` divider over every group after the first.

### Icon buttons and the toolbar

- An icon-only action on the page is `Button variant="ghost" square` with an `aria-label`: undo, redo, clear all, copy (also `nested`, inside a field), Copy URL, and the shortcuts map at rest. One that can do nothing right now drops to 50 % opacity; in a toolbar it is `aria-disabled` rather than `disabled`, so it keeps its place in the toolbar's order.
- **A toolbar is one Tab stop.** The header's controls and the converter's tools are each a toolbar (`role="toolbar"`, named; ADR 0014), driven by the inline script in `Base.astro` like the header menus: ← and → (Home, End) move along its `[data-tool]` controls in the order they show, round from end to end, and the control last reached stays its Tab stop (a roving tabindex; before that its `data-default-tool`, or its first). ↑ and ↓ move between the page's planes (`[data-plane]`: the header, the converter's toolbar, and the box with its table), and Escape on a tool goes back to the box. A control joins a toolbar by carrying `data-tool` with its name; `CategoryMenu`'s `tool` prop does it for its trigger.
- **Slots.** A control an island owns but the static header shows (Copy URL) is drawn into a slot the markup reserves at its final size (`src/lib/slots.ts`, a portal), so it appears after hydration without moving anything and keeps the island's state at hand.
- **Edges line up, glyphs sit inside.** A row of ghost buttons meets the column's edge with its outer button's edge, not its glyph (the first button's at the left, the last's at the right end): a fill (switched on, hovered) then lines up with the box and the table under it, and the glyph sits inside the column as their text does (Sean, 2026-10-08).
- Groups in a toolbar are set apart by `ToolbarDivider` (`h-6 border-l border-line`): in the converter's, undo and redo, then clear all; the category menu leads the row with the calculator and Settings after it, no rules between them (Sean, 2026-10-10; see "Ahead of a row of tools").
- **Switched on.** A ghost button that opens a panel or sets a mode takes `on` while it does (the calculator icon): the accent-soft fill, kept while hovered, alongside `aria-expanded` or `aria-pressed`.
- **Space by what shows.** A ghost icon's 20 px glyph sits 12 px inside its 44 px button, so the space people see between two icons is the gap plus 24 px. Next to a bordered control, which shows its edge, a row of ghost icons keeps the same visible rhythm: the edge sits as far from the last glyph as glyphs sit from each other. The header kept that rhythm, 36 px both ways, until Sean chose the converter toolbar's button spacing for it (2026-10-08): 4 px between buttons and 8 px from the last to the theme menu, as the toolbar's dividers sit 8 px from its buttons, so its glyphs sit 28 px apart and the last 20 px from the menu's edge (`HeaderMenus.astro`). The converter's hint sits 8 px over the toolbar, as the toolbar sits over the box: with the menus borderless, nothing in the toolbar shows an edge under the hint, the menu's text and the icons' glyphs each inset in their buttons (Sean, 2026-10-08; 16 px stood over a boxed menu's edge).
- **Sections and dividers, by what shows** (Sean, 2026-10-15). A line between sections sits evenly between the ink above it and the ink below it, about 16 px each side: the last row's text and the next heading's, in the table, in Edit, and in a panel's foot. A card's first heading sits as far under its top as a panel's title does, about 20 px, never hugging it. Each kind of row takes its own padding to show the same space, since what shows sits differently inside it: a grid's heading is a short line of small text, Edit's a 44 px row with its text 12 px inside (`sectionEdge` in `ConversionTable`). A row or button that fills (hovered, focused, switched on: Hidden, Edit and Done, Edit's headings, the panels' resets) keeps at least 4 px between its fill and a line, the fill being what shows then (Sean, 2026-10-15). Browser tests measure the text's own boxes in every theme, and the fills' gap.
- A successful copy or send swaps the icon for `CopiedIcon`, the check in `text-success`, which every theme keeps at 3:1 on the surface (a graphic, WCAG 1.4.11); `useCopied` (`src/lib/copied.ts`) copies, shows it, and decides when it reverts. On a filled button, where the success color would not show, the plain `CheckIcon` takes the button's ink.
- Keycaps (`Keycap`) are `rounded-sm border border-line bg-surface-raised font-numeric text-xs`.

### Settings

- **One choice of a few** is a `SegmentedControl` (Sean chose it over separate pills, 2026-10-10): the choices joined in one strip, one 2 px edge around all and a line between each, the chosen one filled with the accent's soft tint. Each segment is drawn 32 px tall with `px-2.5` and `text-sm`, smaller than the converter's controls so a panel of settings reads calmly, and still takes a 44 px tap: the label is the target, the shape inside it is what shows. `SegmentedToggles` is the same strip for several at once (fraction sizes). A strip sits in a fieldset whose legend names it, visually hidden where the choices say what they are.
- **One setting that takes effect at once** is a `Switch` (copy buttons): the whole row is the control, the track leading and its label after it, as a checkbox's does.
- **A row reordered by a handle** (Units' systems, `SystemRows`; Sean, 2026-10-15): the handle at the row's end, a ghost icon button with `GripIcon`, its corners the row's (`nested="md"`), `cursor-grab`, `touch-none` so a touch drag never scrolls. The row being moved looks alike however it moves: dragged (`data-dragging`) or with its Move menu open (`data-moving`), it is lifted over the others, `bg-surface-raised` with `shadow-sm`; with focus in it from the keys, the whole row fills, handle included. Dragging and the others slide out of its way on `--motion-base` and `--motion-glide`; let go, it settles into its place. A press without dragging opens Move up and Move down under the handle, drawn as a segmented control is (two moves joined in one strip, `shadow-md`, each seam drawn once, the move with focus turning its own edge the focus color, so the highlight is the strip's edge, never a ring inside it), the way to reorder without dragging (WCAG 2.5.7); Alt+↑ and Alt+↓ move the row from the keyboard; a status line says where it went.
- **A list of choices** (the systems) keeps checkboxes, a row each (`OPTION_ROW`). A checkbox over a group, a system or a table's section, is a `TriCheckbox`: a dash while only some of the group is on, never a plain clear or checked box that hides the difference (Sean, 2026-10-15).
- **A row holding a control is filled as the table's cursor fills a row** (`CHOICE_FILL`; Sean, 2026-10-15): the raised surface under the pointer and while its checkbox has the keyboard's focus, whose own ring stays, since the fill alone is softer than a focus indicator needs. Settings' checkbox rows, and Edit's and Hidden's unit lines and section headings, so the arrows show which unit a key will move as the table's cursor does. A menu's choice is the exception: focus moves with the choice there, so it is ringed inside and keeps the accent fill (`MENU_OPTION`).
- The converter's settings are two side panels (`UnitsPanel`, `DisplayPanel` in `features/converter/SettingsPanels.tsx`), each a `SidePanel`; a part's resets sit under a rule at its foot.

### Side panels

- **A side panel** (`SidePanel`; Sean, 2026-10-15) takes the keys after a click anywhere in it, as the calculator does: on a control, focus goes to it (Safari leaves a clicked button or checkbox without focus); elsewhere, focus comes in onto its first control. It is a card like the calculator's: `CARD` with `p-3 shadow-sm`, a title row (the title in `PANEL_TITLE`, a ghost close button), then its controls. The converter opens one at a time, the calculator, Units, or Display, in `TABLE_SIDE_CELL`: from md a column beside the box and the table, its top level with the box's (`self-start`, spanning the box's row through the last, 1fr, so a tall panel never pushes the table down); below md between the box and the table.
- **Where the keys go**: while focus is inside, its edge turns accent (`PANEL_ACTIVE`, shared with the calculator). A settings panel keeps a panel's keys (`lib/panel-keys.ts`: ↑ ↓ between rows, a strip marked `data-strip` one row, never past the ends; Home and End; ← → within a strip; Enter works a checkbox or a radio; Escape the caller's), and passes typing to the box; it is not modal, so Tab moves on and a press elsewhere leaves it open. The table's own controls take the same keys, Escape ending Edit.

### Calculator

- A card: `CARD` with `p-3 shadow-sm`, in the `Calculator` component; while focus is inside it, where the keys go, its edge turns accent (`PANEL_ACTIVE`: the border and `ring-1` in `--accent`, easing like a shell's edge), as a focused box's does. Introduced and kept 2026-10-08 (Sean). It is a side panel ("Side panels"); the converter places it with `TABLE_SIDE_CELL`, at most `max-w-sm` wide: between the box and the table, flush left, 16 px from each (its margins collapse with the table's 8 px), and from `md` in a column of its own (`w-72`) right of them, its top level with the box's.
- **Header**: the title "Calculator" (`PANEL_TITLE`, `text-sm font-medium text-ink-muted`, labelling the group, as the shortcuts map's title does since 2026-10-08) and a ghost close button.
- **Display**: a field's geometry, `rounded-lg border-2 border-edge bg-surface` around `FIELD_ROW`, so it is the same size as the box; the entry in `font-numeric` stepping down through `NUMBER_SIZES` (`src/lib/recipes.ts`) and keeping its end in view past the smallest; drawn by `NumberText`, so exponent markers and the running value look as they do in a box; a muted 0 when empty; at the row's right, why the entry has no value ("Too large"), in `NO_ANSWER` (`text-sm font-medium text-danger`), as a table row's "Too large" is.
- **Keys** are `Button`s at `min-h-12` with `font-numeric text-lg`, four to a row (`gap-2`): digits secondary; C, ⌫, E, and the decimal mark `tonal`; the five operators `soft`; = primary.
- **Sending**: the `SendButton` under the keys, the row's width (`grid-flow-col auto-cols-fr`, so the gallery's two states share it); secondary, reading "Use" plus the box's unit symbol in semibold, with the copy check (`CopiedIcon`) after the label, drawing itself in (`check-draw`), while a send is confirmed, and `aria-disabled` while there is nothing to send.
- **Focus**: =, the send buttons, and close carry `data-calculator-stop`, the stops Tab cycles through; the other keys are `tabIndex={-1}`, reached by the arrow keys, which move by where each button sits (`nextInDirection` in `src/lib/spatial.ts`), never by an index. What Tab, Enter, a click, and a send do with focus is in docs/UX-SPEC.md §8.

### Links

- A link is ink, underlined in the accent (`underline decoration-accent decoration-2 underline-offset-4`), and at least 44 px tall when it stands on its own line (`inline-flex min-h-11 items-center`). The accent passes 3:1 against the page in every theme, enough for an underline, but not the 4.5:1 text needs, so the words stay ink. The one link today is the not-found page's way back.

### Copy

- **Sentence case** for every label, button, heading, message, and theme name: "Clear all", "Neo-noir", "Copy value". The only capitals inside a phrase are proper names.
- **Units follow the standards, not the sentence-case rule.** Symbols are case-sensitive and never altered: mL, kB, °F, km/h. Unit names are lowercase, including ones named after people (kelvin, newton), except "Celsius" and "Fahrenheit", which the SI Brochure and NIST write capitalized. Chips and rows show the plural name ("milliliters") next to the symbol.
- **Category names** are single capitalized words as labels: Length, Weight, Volume; a name of two words capitalizes the first alone (Fuel economy).
- **Short and plain.** No exclamation marks, no jargon in user-facing text. Error and empty-state text says what to try next.
- **Digit groups never break.** Where text may wrap, digits are grouped with U+202F, the narrow no-break space (the wordmark's lists write `_` for it), and a unit test rejects a plain space between two digits.

## Tuning labs

A visual or motion behavior with more than a couple of settings gets a lab page under `/dev`, so the owner tunes it by eye instead of by description: the real component in the page theme, every setting on a slider that shows its shipped value beside a changed one, settings that persist in that browser, and "Copy settings", which prints them as code to paste over the defaults, built from the settings objects' own keys so none is left out (a browser test checks every key). Every version that shipped stays loadable: when tuned settings ship, the ones they replace join the lab's presets under their version name (`src/pages/dev/_wordmark-lab/presets.ts`), so any earlier version can be compared or copied back as the defaults. A lab's controls live beside its page, in a folder named after it (`src/pages/dev/_wordmark-lab/`), use tokens like everything else, and are tools rather than design-system components, so they stay out of the gallery.

`/dev/wordmark-lab` is the first. It plays the header's wordmark with live settings (timing, pointer response, the mix of phrase kinds, the art's chances, the type steps), can play it without hovering, hold a phrase, show any phrase, or simulate pointer speed, and lists every phrase set in a box the name's size in the page theme. The sheet marks a phrase too long at every step, and a browser test fails if any theme has one.

A design question with a few answers gets a prototype lab instead, each answer built from the real engine and components with simple state of its own, side by side for the owner to try. A prototype lab retires once its answer ships, as the selection lab and the settings lab did, or when a later round replaces it, as the table controls lab did; retiring one follows `CLAUDE.md`'s "Retire a lab" recipe, which leaves an entry in the retired labs index (`docs/research/labs/README.md`) with its notes, screenshots, and last commit.

## Brand assets

The mark is a big circle and a small one on one baseline, on a rounded tile in the accent: it reads like the name, big then small. `apps/web/scripts/brand-assets.mjs` draws it, and everything made from it, from the Daylight theme's tokens into `apps/web/public/`:

| File                   | Use                                                                                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `icon.svg`             | The tab icon, in browsers that take SVG                                                                                                 |
| `favicon.ico`          | The tab icon elsewhere, at 16 and 32 px                                                                                                 |
| `apple-touch-icon.png` | The home-screen icon on iOS: 180 px and square, since iOS rounds the corners itself                                                     |

## Adding a component

1. Check the inventory. Extend before you add.
2. Create `src/components/<Name>.tsx` (TSX: the React API, run on Preact, ADR 0007) or `<Name>.astro` (static, or driven by the inline script).
3. Style with the utilities above, the recipes, and the patterns in this file. Run `pnpm lint`.
4. Add it to `src/pages/dev/gallery.astro` in its real variants and states.
5. Run `pnpm e2e`. Fix any axe violation before merging.
6. Add a row to the inventory table.
