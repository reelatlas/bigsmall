# Design system

Tokens, the Tailwind bridge, the patterns every control follows, and the component inventory. Behavior lives in docs/UX-SPEC.md; this file is how things look and are built.

## Token layers

1. **Semantic tokens** are what components use. They describe a role, never a color: `--ink` is "the text color", whatever a theme makes it.
2. **Themes** assign values to semantic tokens in `apps/web/src/styles/themes/<id>.css`. A theme is nothing but a token set plus, later, an optional decoration stylesheet.
3. **Derived tokens** are computed once in the bridge from semantic tokens (the nested corner radii, and the see-through colors listed in `DERIVED_COLORS`, `src/lib/themes.ts`). They follow every theme automatically.
4. **Component tokens** exist only when a component needs its own knob. None yet. Prefer a semantic token.

Raw values (a hex color, a pixel radius, a literal duration) never appear inside a component, and `pnpm lint` enforces it (see "Token guard"). Artwork is the one exception: the sketches, the brand assets, and the Flip button's particles keep values of their own ("Token guard", "The sketchbook"). If a design needs something the tokens cannot express, add a token, document it here, and define it in every theme. The theme contract test fails until every theme has it.

The full list is the single source of truth in `apps/web/src/lib/themes.ts` (`TOKEN_CONTRACT`), with the contrast pairs every theme must pass (`CONTRAST_PAIRS`).

A derived color is worked out in the bridge from each theme's own (`DERIVED_COLORS` in `themes.ts`), so no theme defines it and it follows a theme's palette when that changes; the theme test mixes it as the browser does and checks its contrast pairs in every theme. One so far: `accent-soft-hover`, the soft tint 60% toward the surface, the unit chip's hover (the full tidy, 2026-10-15; until then a see-through `bg-surface/40`, which the token guard now rejects).

Text that should read quieter takes `--ink-muted`, never opacity: opacity drops below the contrast pairs the themes pass, and differently in each (docs/LEARNINGS.md, "Dim text with the muted ink, never with opacity"). A control that can do nothing right now is the one exception, fading as a whole at 50 % ("States").

## Token guard

`pnpm lint` checks every string in `apps/web/src`, which is where class lists live, and fails on a value that bypasses the tokens. The patterns are in `eslint.config.js` (`RAW_VALUES`). A new pattern is written without "/" (a selector's regex ends at the first one) and tried on a scratch file of violations and allowed look-alikes before it is trusted.

| Flagged                                                                                                                         | Use instead                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Raw colors: hex, `rgb()`, `hsl()`, `oklch()`, `color-mix()`                                                                     | A color token: `bg-surface`, `text-ink`, `border-line`                                   |
| Tailwind palette colors: `bg-red-500`, `text-white`                                                                             | A color token. The palette does not follow the theme                                     |
| Arbitrary values holding a length, color, time, or variable: `w-[37px]`, `bg-(--accent)`                                        | The token utility, or the spacing scale                                                  |
| Numbered durations and stock easings: `duration-150`, `ease-in-out`                                                             | `duration-fast`, `duration-base`, `duration-slow`, `ease-standard`                       |
| Radii, shadows, and fonts outside the tokens: `rounded-xl`, `rounded-full` (a pill; since 2026-10-18), `shadow-lg`, `font-mono` | `rounded-sm/md/lg`, `rounded-nested`, `shadow-sm/md`, `font-display/body/numeric`        |
| A color token made see-through: `bg-surface/40`, `border-edge/[0.5]`                                                            | A derived color in the bridge (`DERIVED_COLORS`), worked out once from every theme's own |
| A number of milliseconds in `setTimeout` or `setInterval`                                                                       | A named constant in `src/lib/timing.ts`                                                  |

Allowed: arbitrary values that name structure rather than a value (`transition-[border-color,box-shadow]`, `grid-cols-[1fr_auto_1fr]`), the spacing scale, and `var(--token)` where the gallery paints its swatches. Raw values belong in the theme files and the bridge, which are CSS and outside the guard. Artwork keeps its own: the sketches' colors in their SVG files, and what the sketchbook sets as it plays (`features/sketchbook/`: the grid's columns and gap from the lab's tuning, on the spacing scale; the art's corner, `TILE_CORNER`; the effects' depths, filters, and offsets; the particles' sizes, shapes, and paths). These pass the guard because it reads class lists; their colors are still tokens, and their times come from `SKETCHBOOK_TIMING` and `BURST_TIMING`.

**When it flags something.** Use the existing token if one fits. If none does, the need is a design decision: bring it to the owner with a recommendation (reuse a token, or add one to every theme) before building on it. Never silence the guard with a disable comment.

## Component rules

Every component in `apps/web/src/components/`:

1. Uses tokens only: no hex, rgb, px radii, or literal durations, and no arbitrary-value utilities where a token utility exists (`duration-fast`, not `duration-[var(--motion-fast)]`).
2. Is keyboard-operable with a visible focus indicator (see "Focus"). A browser test tabs through the page and fails on any stop without one.
3. Has an accessible name: visible label, `aria-label`, or `aria-labelledby`.
4. Has a touch target of at least 44 × 44 CSS px (`min-h-11`, `size-11`, `w-11`), per WCAG 2.5.8 best practice; a control drawn smaller for a mouse keeps the 44 px for a touch screen alone (`pointer-coarse:min-h-11`, the segmented control; Sean, 2026-10-18).
5. Works at 320 px wide and 400 % zoom without horizontal scrolling. Anything added to a row that shares space (the header, the toolbar) is checked at 320 px before it is done, and at small sizes it gives way (a word that becomes screen-reader-only, a row that stacks) rather than shrinking targets. Form controls in a narrow column take `w-full min-w-0`, and code shown on a page wraps (`whitespace-pre-wrap wrap-break-word`) rather than scrolls.
6. Respects reduced motion by using the motion tokens.
7. Appears in `/dev/gallery` in the variants and states that ship, so every theme can be checked against it.
8. Passes the Playwright axe suite on desktop and mobile.
9. Takes what it branches on as a prop, never as children: Astro hands a TSX component its children as rendered markup (`<Keycap label="Mod" />`).
10. Writes ARIA roles, handlers, and `aria-*` attributes out on the element, never through a spread, so jsx-a11y can check them. A jsx-a11y rule that does not fit a sound pattern (click-only rows under `aria-activedescendant`) is disabled on that element alone, with the reason; the token guard is never disabled.
11. Gives a labelled container a role that takes a name (`role="group"`): `aria-label` on a plain `div` names nothing.
12. If it owns keys, moves focus into itself when it opens, onto the control Enter should press, returns focus to its trigger when it closes, and answers its keys only while focus is inside (WCAG 2.1.4), as the calculator does.
13. Sets no margin on its own outer edge: whoever places it spaces it (`TableLayout`'s `TABLE_ROWS_CELL` and `TABLE_SIDE_CELL`), so the same component sits right in any layout and in the gallery. A divider's own spacing is part of what it is (`ToolbarDivider`).

Prefer native elements when they are good enough (`<button>`, radios, `<dialog>`). The converter's box is the one hand-built composite control, on the WAI-ARIA combobox pattern (ADR 0006), its popup the table's place, a grid or a listbox (ADR 0012). A new composite starts from that pattern and the axe suite, and brings in a library only for a measured need recorded in an ADR.

## Patterns

### Recipes

A class list more than one file builds from is a recipe in `src/lib/recipes.ts`, written once so a shared shape cannot drift between Astro and TSX: the cards (`CARD`, and `LIST_CARD` for the table's place), a panel's title (`PANEL_TITLE`), a side panel's card and title row (`PANEL_CARD`, `PANEL_HEAD`, `PANEL_HEADING`), a page's column and its main one (`PAGE_COLUMN`, `PAGE_MAIN`), the content column, centered on every page and the converter's second track, after the page's margin (`CONTENT_COLUMN`, `COLUMN_CELL`), and the converter page's main and footer on its three tracks (`CONVERTER_MAIN`, `IN_CONVERTER_GRID`, `CONVERTER_FOOT`; `FOOT`, every footer's own), a section's heading on a page (`SECTION_HEADING`: About's sketchbook, the not-found page's, the gallery's themes), a disclosure's row (`DISCLOSURE`, Every formula's categories and Show all over them), the links (`LINK`, `QUIET_LINK`, `INLINE_LINK`), a group's title (`GROUP_TITLE`), a count beside a label (`COUNT`), and the word and its count on one baseline (`LABEL_WITH_COUNT`), a line over a row or a foot that fills (`ROW_RULE`), a side panel's accent edge while it has the keys (`PANEL_ACTIVE`), a section's name stuck under the head (`STUCK_HEADING`), the fluid shells (`SHELL`, `SHELL_PANEL`; each shell's resting style beside its one use), the menus (`MENU_ROOT`, `MENU_SIZER`, `MENU_SIZER_LABEL`, `MENU_SHELL`, `MENU_TRIGGER`, `MENU_CHEVRON`, `MENU_OPTION`, shared by the theme menu and the category menu), a row in a list of choices (`CHOICE_ROW`: a setting's row, `OPTION_ROW`, Units' systems; a menu's choice, `MENU_OPTION`; More's items), the fill of a row holding a control, under the pointer and with focus (`CHOICE_FILL`), a unit's symbol wherever it shows, and its name beside it (`unitSymbol()`, `unitName()`), the short message for a value with no answer (`NO_ANSWER`), a message in place of a list's rows (`LIST_MESSAGE`), the field row (`FIELD_ROW`) and a field's resting edge (`FIELD_EDGE`), the text fields (`FIELD_STACK`, `FIELD_LABEL`, `TEXT_INPUT`, `TEXT_AREA`), the rows a field's cursor moves through (`CURSOR_ROW`, and `rowFill()` for their fill), the type ladders (`NUMBER_SIZES`, `WORDMARK_SIZES`), and the wordmark's face and lines (`WORDMARK_FACE`, `PLAYING_LINE`, `ART_LINE`).

- A recipe whose look depends on a state is a small function returning class lists (`rowFill(selected, current)`, `unitSymbol(alone)`, `unitName(shown)`), so the states can never both apply and fight over one property.

- A list only one file uses stays in that file, as an UPPER_SNAKE constant beside its markup (`TEXT_LAYER` in ValueField, `DISPLAY_TEXT` in Calculator). It moves to `recipes.ts` when a second file needs it.
- A recipe holds only what every use shares. A part one use needs and another must not have goes in that use or in a variant recipe: merging the shells once gave the shortcuts map a fading edge (docs/LEARNINGS.md, "Merging recipes can undo a fix").
- TSX joins class lists with `cx()`, which leaves out any a condition turned off (`cx('font-semibold', !compact && 'text-ink-muted')`); Astro joins them with `class:list`. Never a template string with `? '' :`, which leaves stray spaces.
- Recipes hold tokens only, like every class list, and the token guard checks them.

### Edges and borders

- **2 px is a control's edge.** Fields, secondary buttons, and the table's place (`LIST_CARD`, the box's popup, whose rows people pick) share `border-2` in `--edge`, so no control looks lighter-edged than its neighbor (the table's since Sean, 2026-10-08). A border is the one edge children cannot paint over; an inset ring is drawn under them, which is how row highlights once ate into it.
- **1 px is a divider or a keycap.** The line under a menu's trigger, between the matches' groups, the toolbar divider (`border-l`), and keycaps use `border`. A card is 1 px in `--line` (the calculator, the lab's panels), a light frame for what comes and goes.
- **Open is accent.** A shell's edge is `border-edge` at rest and `border-accent` while open or while something inside has focus; a ghost menu, with no edge at rest, draws its open edge as a 2 px outline inside its card (`MENU_SHELL`), which takes no room. The calculator's card does the same while focus is inside it: its 1 px border and a 1 px ring turn accent, 2 px like a focused box, so nothing moves.
- **A control's edge identifies it.** `--edge` passes 3:1 against the page and the surface in every theme, so a field's resting edge meets WCAG 1.4.11 by itself, and the theme test enforces it. `--line` stays subtle because a divider only groups. Each theme's `--edge` is its `--line` moved toward `--ink` to the first step past 3:1. Introduced 2026-10-06 as a trial (findings-0, sixth pass) and kept (Sean, 2026-10-15).

### Focus

- **One ring.** The base layer gives every `:focus-visible` element a 2 px `--focus` outline offset by 2 px. Buttons, chips, and links rely on it and add nothing. A drawn control whose input is out of sight takes the same ring on its box when the input has focus (`focus-ring-peer`, the `Checkbox`).
- **Never pair `outline-none` with focus utilities.** In Tailwind v4, `outline-none` sets the outline style to none, and `focus-visible:outline-2` then draws nothing (docs/LEARNINGS.md).
- **Inset where an edge clips or crowds.** `focus-ring-within-inset` on the menus' option labels; `focus-ring-inset` on a control flush in a filled row (Units' handles), so the ring follows the control's corners inside its row (Sean, 2026-10-15). Joined pieces (segments, the Move menu) take focus on their own edge instead (`SegmentedControl`).
- **Shell edges for fields and open shells.** The field's input sets `outline-none`; its shell's accent edge (`focus-within:border-accent`) is the indicator. The shortcuts toggle shows the ring while closed and none while open (`group-data-open:outline-none`): the open shell's accent edge says where focus is. The menus' triggers show the standard ring, nothing clipping them at rest; while open, focus is in their list.
- **A tap never moves focus into a text field.** On a touch screen that brings the keyboard up, so a control that puts the caret back in the box after a click or a key leaves focus where it is after a tap (`pressedByTouch()`, `src/lib/modality.ts`; ADR 0015). A control that closes on `pointerup` (the category menu's choices) ends the tap with `preventDefault()` on `touchend`, or the browser's click after it lands on what the control uncovered.
- **The list is never focused.** Rows are virtually focused through `aria-activedescendant`; the listbox has `tabIndex={-1}` so Chrome does not make it a Tab stop.
- **Focus moves without a scroll of its own under a stuck head.** A panel's first control and a closed panel's button take focus with `preventScroll`, the layout having placed the panel, and the page scrolls only when the control's measured box is outside the window (`focusStill`, `Converter.tsx`; `SidePanel`, `Calculator`): Chrome's own focus scroll trusts the static layout, which a stuck bar's child does not have (docs/LEARNINGS.md, "Chrome scrolls to a focused control's static place inside a sticky bar").

### States

One look per state, defined here and taken by every control; a component adds none of its own (Sean, 2026-10-18: one logic and one language for the states, variants named where a shape needs one).

- **Hover** (a pointer; a touch screen has none, ADR 0015): a row or a ghost control fills with the raised surface (`hover:bg-surface-raised`, `CHOICE_FILL`, `rowFill`); an accent fill steps to its hover tone, derived in the bridge from the theme's own, so the label keeps its ink (`accent-soft-hover`: the chip, the soft button; `accent-hover`: the primary button, 2026-10-18, 90 % opacity until then); a text control takes the ink and the accent underline (links, tabs); a control that is on keeps its look under the pointer (`Button`'s `ON`), so on never flickers back.
- **Focus**: the one ring ("Focus").
- **Pressed**: a button steps to 80 % while held (`active:opacity-80`); rows, segments, and checkboxes change on the press itself and need no held look.
- **On, chosen**: the accent's soft tint (`bg-accent-soft`: a checked segment or menu choice, an `on` ghost button, the box's unit row); a mark that is on takes the full accent (`Checkbox`'s box, the primary button's fill); a chosen tab takes the ink and the accent underline, as a link does under the pointer.
- **Current** (the cursor, the row a key will act on): the raised surface (`rowFill(false, true)`, `CHOICE_FILL`'s focus-within), softer than chosen, never the accent.
- **Disabled, or busy**: the control keeps its place and size, takes the arrow ("Cursors"), and fades as a whole to 50 % with its label (`disabled:opacity-50`, `aria-disabled:opacity-50`: buttons, tools, menu items, keys; a whole strip through its fieldset): WCAG asks no contrast of an inert control, which is why opacity is right here and wrong for quieter text ("Semantic tokens"). Two variants with the same logic: a switch that is fixed while its row still informs fades its box alone (the box's unit in Edit, `Checkbox`); a segment inert alone in a joined strip takes the muted ink (the Move menu's end), since a fade would cut the strip's shared edge. `aria-disabled` where the control must keep its Tab stop (a toolbar's tools, the calculator's Use, a reset, a form sending), `disabled` where it may leave the order.
- **Wrong, or nothing to show**: a message in the danger ink (`NO_ANSWER`, a row's "Too large", the failed send line), never a red edge; an empty state says what to try (`LIST_MESSAGE`).

### Motion

- **The wordmark at play** is driven frame by frame from script, as the sketchbook's stepped changes are: frames come from `requestAnimationFrame` only while the heading (the name and its art) is hovered or a tap plays it, its pace comes from the pointer's speed, and it never starts under `prefers-reduced-motion`. Other motion is a CSS transition on the motion tokens, or, where a script must place it, an animation on the Web Animations API: the glide and the flash below, and the sketchbook.
- **The sketchbook at play** (`features/sketchbook/`; what it does, the effects, the waits between a tile's own changes, Pause, and the flash limits, is docs/UX-SPEC.md §1, "About"): a change runs between a tile's layers, the sketch showing, the one arriving, and the pieces the cutting effects need, for `SKETCHBOOK_TIMING`'s lengths (`lib/timing.ts`). The stepped effects (Glitch, Scramble, Scan) step frame by frame at `frameMs`, their frames and clip-paths planned in `frames.ts`; the rest run on the Web Animations API, on the theme's `--motion-ease` or `--motion-glide`, or on a spring, a curve no theme has, tried in its lab: shipped, it becomes a motion token in every theme. Doors takes its depth from the tile's own `perspective`, its halves clipped to the tile and fading over the second half of their swing, so no engine leaves one standing at the end (docs/LEARNINGS.md, 2026-10-16). The limits live in the code, not in the lab: `FLICKER_SHARE` caps what one frame changes, `SKETCH_MIN_GAP_MS` how often a tile changes by itself, and a unit test holds the frame planner to them. Under reduced motion nothing runs by itself, and a press cross-fades.
- **The Flip button's answer** (`features/sketchbook/burst.ts`; the moods are in docs/UX-SPEC.md §1, "About"): `particles()` plans a press's particles in a mood (pure, tested in node) and `burst()` plays them behind the label on the Web Animations API, for `BURST_TIMING`'s lengths on `--motion-glide`, in the theme's accent, its soft tint, and its art colors; three moods are small pictures, the rest shapes of CSS; a press while they play adds to them, and the oldest go past ninety. Particles are artwork, like the sketches: their sizes, shapes, corners, and paths, the fireflies' glow, and the bubbles' and ripples' edges are set in `burst.ts`, not taken from tokens ("Token guard"). Under reduced motion it flashes the button's fill instead (`flash()`).
- **Type that steps to fit.** Text that may not fit its box steps down a type ladder (sizes, largest first, in `src/lib/recipes.ts`) and takes the largest size at which it fits: never a size in between, and never clipped. Two mechanisms measure it, one per kind of box. `useFitStep` (`src/lib/fit-step.ts`) fits text in an island that clips its own box, re-measured on every render and on resize: the calculator's display on `NUMBER_SIZES`. `useFieldFit`, beside it, fits a field's whole row in one pass and a fixed order: the chip's name gives way first, then the number steps down `NUMBER_SIZES`. `fitPhrase` (`src/lib/wordmark-motion.ts`) fits a line laid over a fixed room, once per phrase: the wordmark on `WORDMARK_SIZES` through `fitSteps()`, which may also set two lines with `leading-tight` (`text-sm` and `text-base` keep two lines within the name's height, or nearly). A transform squeezes only a phrase too long at every step, which the wordmark lab flags and a browser test rejects. New text that must fit uses one of the two with a ladder, never a third way; a column that may not fit gives way whole through `useColumnsFit` instead (see "Columns that give way"). All three measure again when their box changes width and when the theme changes, since a theme's fonts change what fits; a change of height alone, a field's row wrapping, refits nothing.
- **Nothing clips a moving line.** Before its line leaves the flow, the wordmark holds its box at the name's size, width and height, and releases it when the line settles home, so nothing beside it moves. It never clips the box, so descenders and tall symbols show whole; each frame fits by construction instead (a flipping letter is never wider than the room its phrase leaves).

- Components write `transition-colors` (or `transition-[border-color,box-shadow]`, `transition-transform`) and nothing else: the bridge makes every transition default to `--motion-fast` and `--motion-ease`.
- Buttons, chips, and shell edges fade; list rows and theme options change instantly, so keyboard movement never lags.
- **A check that draws itself in** (`check-draw`, `global.css`) confirms an action done in a button with a label, such as Settings' resets and the calculator's send (Sean, 2026-10-10): `CheckIcon` in the success color after the label, its stroke drawn over `--motion-slow`. It rests fully drawn and animates from hidden, so reduced motion, which stops every animation, shows it whole. An icon-only button confirms by swapping its icon for `CopiedIcon` instead ("Icon buttons and the toolbar").
- **A unit moving between shown and hidden glides and flashes** (Sean, 2026-10-15). In one length, three beats: what leaves fades out in its first 30 %, before anything slides over where it was; what moves glides throughout; what arrives fades in over the second half, once what moved out of its place has gone, so nothing lingers as a ghost the rows slide through. The glide (`features/converter/glide.ts`) measures where each part of the table sits on the page (never the screen, so a page that scrolls as the table changes moves nothing), renders the change at once, and slides each part that moved from where it was (a unit keeps its key in its row or its line in Hidden, so it travels between them), fading in what is new and fading out a copy of what left where it was, over `--motion-slow` on `--motion-glide`; the card clips what slides in from outside it. A theme's `--motion-ease` suits a fade or a shell opening, not travel: it does most of its movement in the first fifth, and a glide on it reads as a jump (Sean, 2026-10-15). It moves the rows themselves, not pictures of them, so the page takes clicks throughout (docs/LEARNINGS.md, "A view transition takes no clicks"). The flash (`lib/flash.ts`) is the accent's soft tint, held for a fifth of `--highlight-fade`, then fading back to the element's own fill on `--motion-glide`: on a row or a Hidden line that arrives, and on Hidden when units go into it.
- Reduced motion zeroes the motion tokens with an unlayered rule placed after the theme imports (a layered rule loses to the themes' unlayered token blocks), and a blanket `!important` rule stops any other transition or animation. A browser test checks the tokens read `0ms` in every theme. `--highlight-fade` is not zeroed: a highlight is a change of color, no movement, and it keeps telling where a unit went (it runs as a script animation, which the blanket rule does not stop).

### Corners

An element inset inside a rounded shell uses the shell's radius minus the inset, border included, so the curves stay concentric; an inner corner as round as the outer one looks swollen.

- `rounded-nested`: inside a field or its list (`lg` shell, 2 px border, 8 px inset). The chip, the box's clear and a row's copy button (`Button nested`), and list rows.
- `rounded-nested-md`: inside a menu (`md` shell, 2 px border, 4 px gutter) or a setting's row. The theme menu's options, and Units' handles (`Button nested="md"`).
- `rounded-mark`: a mark whose shape carries meaning, the checkbox's 16 px box, which must read as a square since a circle says radio (Sean, 2026-10-18). The theme's small corner capped at a quarter of the box's side (`min(--shape-sm, spacing 1)`): Sakura's 8 px and Daylight's 6 become 4, Theorem's 4 and Hardhat's 2 stay their own, so a theme keeps its corner up to where a square would stop reading as one; the small corner alone, 8 px on 16, had made a circle.

### Responsive layout

- **Decide by the box, not the layout.** Whether something fits is decided by measuring its own box (a field's number and chip, `useFieldFit`) or by its container's size (the header's menus, the start's tiles), never by which layout it is in, a breakpoint standing in for its width, or a count of characters, so one component reads right in a wide box and on a phone. Where the converter places its pieces lives in one place, as named class lists (`TABLE_GRID` and its cells in `TableLayout.tsx`), never inside a component.
- **Tiles by their container.** The start shows the categories two across, and four once the table's place, an `@container`, is 512 px wide (`@lg:grid-cols-4`): the smallest stock container size above the widest case, Theorem's "Temperature", which needs a container of 456 px. A browser test pins both sides in every theme, and the field's arrows read how many tiles sit in a row from the layout, never from a count.
- **A column beside the rows.** The content column (`CONTENT_COLUMN`, the `xl` container size, 576 px: the narrowest stock width at which the box keeps every unit's name beside a ten-digit number, measured 2026-10-17: at 528 px four of the eight longest names drop, at 512 five; the table keeps every name from 512) is centered on every page with the header on it, so the header sits in one place from page to page and the frame reads the same (Sean, 2026-10-18: one layout that scales across pages, no room kept for a panel that seldom shows; from 2026-10-17 the converter's column sat at the page's left with a second track empty beside it most of the time, and About's column was 672 px). From `md` the converter page's `main` spans the window (`CONVERTER_MAIN`) and is one grid of three tracks (`CONVERTER_GRID`; `grid-cols-margin-box-and-side` in global.css): the page's margin, the column's cap, then a side panel's own width. That morning the column and the panel re-centered as a pair on the page column, the column sliding 168 px on every opening. The header, the intro, the toolbar, the box, and the table sit in the second track (`COLUMN_CELL`) and the panel in the third, spanning the box's row through the last of the converter's four rows, `auto auto auto 1fr` (`TABLE_SIDE_CELL`, `self-start`), its top level with the box's (Sean, 2026-10-15). Every block between the page and the cells spans the three tracks and hands them on with a subgrid (`IN_CONVERTER_GRID`: the island's section, the layout's root, its grid), so one declaration places all of it and the header's menus end where the box ends. The converter page's footer is the same three tracks (`CONVERTER_FOOT`), its line in the column's track, so the About link follows the column when a panel slides it (Sean, 2026-10-18: the foot aligned to the column wherever it is; until then the footer sat on the page column and stayed put). The page column (`PAGE_COLUMN`, `5xl`, 1024 px) bounds the other pages and their footer; it was the stock size above the pair and the frame. An item that spans a `1fr` track sizes only that track, so a panel taller than the box and the table adds its height under the table, never between the box and the table (docs/LEARNINGS.md). Below `md` the panel opens on the column between the box and the table. Until 2026-10-15 the calculator's card was a subgrid of the first three rows, its title row on the toolbar's line and its display level with the box.
- **The page's two ends mirror** (`--page-frame`, one spacing token, read as `px-frame` by `PAGE_COLUMN`, `pt-frame` by `PAGE_MAIN` and `CONVERTER_MAIN`, `pb-frame` by the footer, and `-mx-frame px-frame` by `PAGE_BLEED`, which takes the same back; a trial, 2026-10-18). Rows of controls sit on the gutter with their boxes and their ink inside, as a row of ghost buttons meets the column's edge ("Edges line up, glyphs sit inside"). The header's row is 48 px: each control's 44 px target sits in a 48 px slot (the menus' `h-12` placeholders, the icons' `size-12` slots: 2 px of room for an open shell's edge, as a field has its 2 px border), the name centered beside them, 6 px of air over its line. The foot is a line of text on the same padding and on the content column like the header (on the converter page in the column's track, `CONVERTER_FOOT`, so it follows the column): the About link, its 44 px target taken back into its line (`QUIET_LINK`), or About's privacy line, so both pages' feet sit alike, their text starting where the name does with the frame between it and the edge, and nothing invisible adds to either end (Sean, 2026-10-18). Between the content's end and the foot 48 px (`pb-12` on the page's main), the same on every screen, so a long page's last card does not hug the foot, which keeps its frame at the edge (Sean, 2026-10-18: "it feels like part of the content"; three frames, tried first, read too big beside a desktop's table, and 48, the section step's compact value, right on both). A browser test holds the frame to one value on every side at a phone's width and a desktop's. A minimum height on the footer would not make a row of it: with border-box sizing the padding counts inside it (docs/LEARNINGS.md, 2026-10-18).
- **Sections step by the frame** (`--spacing-section`, `mt-section`; Sean, 2026-10-18, chosen in the tidy lab from 2, 3, and 4 times the frame): a page's sections are three frames apart, 48 px on a compact screen and 72 from `sm`, one token in place of About's two pairs of numbers (48/80 to the sketchbook's heading and 64/96 to the tabs until then). The not-found page's section, a dev page's tools, and the labs' blocks take the same step (Sean, 2026-10-18: the same tokens on every page; the not-found heading sat 40 px under the header until then), and a line under the header, the converter's intro or a dev page's, sits 24 px under it. So a page's vertical rhythm is four things: the frame at its ends, the section step between its sections, 48 px before its foot, and the spacing scale inside a section (24 under a heading or over a tab's panel, 8 between the box and its list). A gap is set on the thing that follows (`mt-`), padding only inside a box (`pt-6` in a tab's panel), and `gap` where a stack is a flex or grid of equals.
- **Ahead of a row of tools.** A control that leads a row of icon buttons (the category menu before the converter's tools) sits at the row's left and the tools at its right end while both fit; where they do not, the tools keep the line and the control wraps onto one of its own under them, both flush left. The control comes first in the markup, and `flex-wrap-reverse` with `justify-between` (`TABLE_TOOLS_ROW` in `TableLayout`) stacks a wrapped row's first line at the bottom and puts a line's one item at its start. The browser's own fit decides, in every theme, with no breakpoint to measure; a browser test pins both sides, and the toolbar's arrows follow what shows (ADR 0014). Introduced 2026-10-08 as a trial in its own commit, the control first at the row's end, then moved to its start the same day, as the more logical order of controls; kept for now (Sean, 2026-10-08). The tools had drifted to the right end on their own line too (an `ml-auto`); both lines are flush left again (Sean, 2026-10-15).
- **Switch at a container size, measured.** CSS cannot see a row wrap, so a row that must change layout when it no longer fits switches at the smallest stock container size above its widest case, not at a one-off breakpoint. The page header is an `@container`: its icons, Copy URL among them, hide under `@max-sm:`, 384 px of header, where Hardhat's name with Copy URL and the theme menu, the widest case, needs 347; and the theme menu takes a line of its own under `@max-xs:`, 320 px, where the name and the theme menu alone need 297 (the menus wrapped under `sm` until 2026-10-17; the widest case was 452 while the layout switch stood beside the theme menu, ADR 0013). Browser tests pin both sides of the switch in every theme.
- **Columns across rows of buttons.** A list whose rows are buttons with a separate button beside each (the table's rows and their copy buttons, the active one laid over its row's end), is one grid, each row and its main button spanning it with `grid-cols-subgrid`, so names, values, and symbols line up in columns while no control sits inside another.
- **Columns that give way.** A grid column that is good to have but not needed to read a row (the table's names, beside the symbols) keeps its cells to one line, clipped, and marks them `data-column`; `useColumnsFit` (`src/lib/fit-step.ts`) shows it while every one of its cells fits whole and hides it in every row at once otherwise, so rows never wrap, clip, or differ from each other. More such columns join it in the order they give way: the pairs' names (`pair`) first, the table's longest, then every name (`name`), then Both's fraction (`second`). A column may have stand-ins, cells marked `data-instead` with its name, which show exactly where it hides: Both's fraction moves under the decimal, on a second line in the value's columns (Sean, 2026-10-15). What the column holds stays for screen readers in a copy of its own. Introduced 2026-10-08 (Sean: names wrapped beside long values on an iPhone 13).
- **As wide as the widest label.** A control whose label changes while it is used (the theme and category menus) takes its width from an unseen sizer in flow (`invisible grid h-0`) that stacks every label in one cell (`col-start-1 row-start-1`) with the control's padding (and border, where it has one), so it never jumps between labels.

### Fluid shells

A control that opens a list or panel keeps both in one shape, drawn over the page so nothing reflows. Its native semantics stay inside the shell (the theme menu is a `fieldset` of radios), because a native popup such as a `<select>`'s list is drawn by the OS, where no token reaches. Its recipes live in `src/lib/recipes.ts` and every instance builds from them:

- A **placeholder** with `group relative` and a fixed size holds the layout: `h-12` for the theme and category menus (the category menu as wide as its widest label, through an unseen sizer; open, twice that, its choices in two columns each as wide as the menu, so its counts, bare numbers, keep the room its chevron takes), `size-12` for the shortcuts map. It carries `data-open` while open.
- The **shell** inside takes `SHELL` (2 px edge and the open state: `z-20`, accent edge, `shadow-md`; no motion, since a shared part must not decide how a variant moves), a resting style kept beside its one use, and its own position and radius. Each shell clips as its shape needs: the box always, the shortcuts map only while open, so its icon's focus ring shows at rest (Sean, 2026-10-15).
  - Bordered (`FIELD_SHELL` in `ValueField`): bordered at rest, clipped, `bg-surface`, accent on `focus-within`, and its edge eases between edge and accent, because the shell stays in view through the change. The box (`rounded-lg`, plus `shadow-sm` at rest); the theme and category menus took it too (`rounded-md`) until the trial below.
  - Ghost (`GHOST` in `ShortcutsHelp`): a borderless icon button at rest that becomes a card when open, its icon then switched on in the accent's soft fill, as the toolbar's buttons are while their panels are open (Sean, 2026-10-15). Nothing eases: its panel appears and vanishes at once, so its edge must too, or a fading accent square is left around the icon. A browser test checks the ghost edge cannot animate. The shortcuts map (`rounded-md`), anchored with `absolute top-0 right-0` so it grows left and takes its width from its panel. The theme and category menus take a ghost shell of their own (Sean, 2026-10-08), `MENU_SHELL`, so they compete less with the box and the table: nothing at rest, so the trigger (`MENU_TRIGGER`) is all there is, as wide as the menu, which is as wide as its widest label, with a ghost button's tint, corners, and focus ring, 44 px tall like the icon buttons, 12 px from each edge to the label and the chevron, open or closed. Open, the shell becomes the card around the trigger and its list, the same size (the category menu's twice as wide, for its two columns: `w-2/1` over `inset-x-0`, the trigger spanning both); its accent edge is a 2 px outline drawn inside the card's edge, which, like a border, nothing inside can paint over and, unlike one, takes no room, so nothing moves when it appears.
- A **menu** inside a shell is a trigger (`MENU_TRIGGER`: 44 px, the value alone and its chevron, `MENU_CHEVRON`; the category menu shows its own name, "Category", muted before a choice, as a field shows its placeholder; the theme menu showed a muted label "Theme" before its value in a wide header until 2026-10-17, Sean: one behavior for both menus) over a `fieldset` of radios in `SHELL_PANEL`, each a label (`MENU_OPTION`: 44 px, `rounded-nested-md`, the checked one in the accent's soft fill, focus ringed inside). Open, a trigger reads its label instead of its value ("Theme", "Category"), muted, heading the list as the shortcuts map's title heads its panel, the checked choice's fill marking the value; introduced and kept 2026-10-08. The theme menu and the category menu build from the same three.
- The list or panel renders inside the shell, in flow, under a `border-t` divider (`SHELL_PANEL` for a header menu's panel, which shows only while open). `overflow-hidden` clips it to the corners; the shell's own border is never clipped. A list that can outgrow the window (the category menu's) is held to it, measured as it opens and when the window resizes: from its top to the window's bottom, less 8 px, never under four rows, scrolling inside (`overflow-y-auto overscroll-contain`), the chosen choice scrolled into the list's view by the list's own `scrollTop`, never the page's (Sean, 2026-10-16).
- A shell that opens inside a scroll container rises to the **top layer** while open (ADR 0023): the category menu's shell becomes a popover (`popover="manual"`, `showPopover()`), placed over its root by `position: fixed` from the root's rect, twice the menu's width as its classes say but never past the toolbar's right edge, and placed again as anything scrolls or the window resizes. Its classes take back what the browser's popover styles set (`POPOVER_RESET`: `m-0 border-0 p-0 text-ink`), its `data-open` styles still apply since the DOM is unchanged, and the attribute goes on only while open, a closed popover being `display: none`. A browser without popovers opens it in place. What every menu in a shell does while open is one hook for the islands' menus (`useShellMenu`, lib/shell-menu.ts: the category menu and More): a press outside or focus leaving closes it, Escape closes it back on its trigger, and ← and → close it and hand the key to the toolbar, which moves on from the trigger; the header's menus do the same in Base.astro's script (ADR 0002).
- A **dropdown under an icon trigger** (`MoreMenu`): the third shape, for an icon-only control whose list has no label to grow around. The trigger is a ghost icon button switched on while open; the panel a card under its right edge (`SHELL`, `rounded-md bg-surface p-1`, `w-max min-w-44`), its items rows with the tool's icon, muted, and its label (`min-h-11 rounded-nested-md`, the raised surface under the pointer, `focus-ring-inset`, half strength when the tool can do nothing).

### Fields

The converter's box is `ValueField`, placed by `TableLayout`: it takes a shell's edge (`SHELL`, `FIELD_SHELL`, `rounded-lg`, plus `shadow-sm`) without ever opening, its list being the table under it.

- **Text fields** (`FIELD_STACK`, `FIELD_LABEL`, `TEXT_INPUT`, `TEXT_AREA`): a label over its input in a stack, the input 44 px with the fields' 2 px edge on the surface, its text 16 px (`text-base`), the size under which a phone zooms into a focused field (docs/LEARNINGS.md, 2026-10-17), its label 14, a message 128 px tall; the feedback form's (ADR 0024), and the labs' controls take the same.
- **Row.** `FIELD_ROW` (`src/lib/recipes.ts`): 60 px tall inside the 2 px border, `pl-4 pr-2 gap-2`. The 44 px chip keeps the same 8 px from the top, bottom, and right edges, and the value starts 16 px in.
- **Text layer.** The value is drawn by an `aria-hidden` layer over an input whose own text is transparent (`text-transparent caret-ink selection:bg-accent-soft`). The input keeps the caret, selection, focus, mobile keyboards, and the accessibility tree; the layer gets the typography, which is how the exponent marker in `1.5E21` is `font-semibold` (core's parser reports where it is). The layer matches the input's font, size, and line box, follows its horizontal scroll, and is `pointer-events-none`.
- **Size steps.** `useFieldFit` (`src/lib/fit-step.ts`) picks the largest of the five `NUMBER_SIZES` (`text-2xl sm:text-3xl` down to `text-base`) at which the layer's text fits on one line, measured before paint on every render and whenever the row changes width (see "Type that steps to fit"). - **Two pills** (Cooking, ADR 0021). The same fit, in the same order, then one step more: what gives way does so one part at a time, the unit chip's name, then the ingredient pill's chevron (the cue that the pill opens a list, so it outlasts the name), each with the number stepping down beside it; only where it fits at no size beside both pills does the row wrap, the measurement setting `data-wrap` on it (never the browser's own wrapping, which judged by the pills' full names and wrapped a desktop's box where one line fit), the pills one group on the second line, the name and the chevron back, in that order, where both fit whole there, the ingredient's name cut short only where that line is too narrow (Sean, 2026-10-16).
- **Chip.** Symbol, then plural, on one baseline (`items-baseline`). - **Clear.** While the field holds text, a ghost square button with `ClearIcon`, a × in a circle, right after the text and before the chip, so the chip's plain × reads as the chip's own (Sean, 2026-10-15). - **Chip of a pair** (ADR 0026): every chip's, the symbol then the name (`ft in feet and inches`), the name giving way as any chip's does; a chip of the name alone went blank where the name gave way, the fit's write left in place (docs/LEARNINGS.md, 2026-10-19) (Sean, 2026-10-19).

- **Category menu** at the left of the toolbar row over the box, its left edge on the box's, or on a line of its own under the tools, flush left, where the row has no room (see "Ahead of a row of tools"). ### Lists

- Rows sit in a `p-2` gutter, each `rounded-nested px-2`, so a highlight sits inside the edge with the same 8 px as the chip and the row text starts 16 px in, under the value.
- **Matched letters** are set heavier and nothing else changes: names `font-semibold`, category names `font-bold`, a symbol's matched part `text-ink`. The span comes from core's `matchSpan`.
- **The cursor's lists** (the table's units, the matches, and the start's tiles): cards (`LIST_CARD`) with the same `p-2` gutter, each row `CURSOR_ROW` (`min-h-11 cursor-pointer rounded-nested px-2`). Their fill comes from `rowFill()`: the unit in the box in `bg-accent-soft`, the chip's color; the row the cursor is on, or the pointer is over, in `bg-surface-raised`, the muted tint of a hovered row, never an outline. The accent fill marks the selection, so the cursor takes the quieter tint. No transition, so keyboard movement never lags.
- **No value yet** is an em dash (`NO_VALUE` in the converter's state) in `text-ink-muted`, read as "no value" by screen readers, with no copy button.
- **A control shown only on the active row** (the copy button) is laid over the row's end on a short fade of the row's own fill, no column kept for it (`COPY_CELL`, `copyBehind` in `ConversionTable`); on the other rows it stays in the accessibility tree with `opacity-0 pointer-events-none`, never `invisible` or `hidden`, so screen readers reach it and a tap at a row's end takes the row (docs/LEARNINGS.md, "A copied number pastes as a number").
- **The scrollbar's room is kept** (`scrollbar-gutter: stable` on `html`, global.css; Sean, 2026-10-18): a classic scrollbar takes layout width the moment a page outgrows the window, and a centered column would step left by half of it as a side panel opened; with the gutter reserved the column never moves, at the price of an empty strip where the bar would be on a page shorter than the window, on Windows and Linux alone, since overlay scrollbars take no room. Two consequences: the window widths these docs name are the content's, so on a classic-scrollbar system add the bar's 15 px, and the browser tests size their windows by the content (`windowOf`); and the centered page column starts on a whole pixel (`mx-page`, global.css: the start margin the odd remainder's half rounded down), since auto margins would split it into halves and put the sketchbook's tiles on a half pixel.
- **Stuck layers** (docs/UX-SPEC.md §1, the head, the toolbar and the box; §1 "About", the formulas): a part that stays at the window's top while what is under it scrolls is `sticky` with the canvas behind it, and a part stuck under another sits a pixel under its measured edge (`style.top` from a ResizeObserver; docs/LEARNINGS.md, "Stacked sticky headers"), inside its own section so the next one pushes it up (the table's section names, and since 2026-10-18 Edit's and Hidden's headings with their checkboxes, one rule wherever a name heads a list); and a block over two grid rows is a subgrid, so what sits beside its second row keeps its place (the side panel on the box's top). The layers, lowest to highest: the rows (no z-index), a section's name (`STUCK_HEADING`, 5), the head (`TABLE_HEAD_CELL`, 10), an open shell (`SHELL`, 20); a side panel is `isolate`, so its own layers stay inside it. A rule that should show only while stuck comes from a sentinel 2 px over the part's top edge watched by an IntersectionObserver (`data-stuck`), drawn by a pseudo-element so it takes no room; nothing sticks where the window is too short for the part, a name, and three rows, measured; and a control that may pass under a stuck part meets the target minimum on its own (`Checkbox`, "A list of choices"), so nothing lets go for a small target (2026-10-18; until then the head let go in Edit, with Hidden open, and with a panel below md, since axe's target-size counts a 16 px box within 24 px of another as cramped whatever covers it). One of these is a stand-in for platform behavior, to retire when it arrives (Sean, 2026-10-17: patterns, not band-aids): the sentinel for `@container scroll-state(stuck: top)` once WebKit supports it. The other is a choice (ADR 0025, 2026-10-18): the page opts out of the browsers' scroll anchoring (`overflow-anchor: none` on `html`), WebKit having none and Chrome's being a heuristic that once pulled the page up as a panel closed under the stuck head, and what must stay put across a change above it is kept by hand in every engine alike (`keeping` and `useKept`, lib/keeping.ts: the box across a table swap, the table's card as Edit starts and ends, the formulas' categories, About's tabs); Chromium already finds nothing to do in either. The canvas behind a stuck layer reaches one step past its column on both sides (`before:-inset-x-1` on the head, down through its strip), so a card's ring or shadow passing under it paints behind it, not beside it (Sean, 2026-10-18: the panel's accent ring showed along the head's edges).
- **Sections** in the table: a header row in `PANEL_TITLE` (`px-2 pb-1`), a `border-line` rule over every section after the first; a section's checkbox in Edit and the Hidden list sits on its heading, its units' checkboxes set in `pl-8` under it, as a tree's children. ### Icon buttons and the toolbar

### Cursors

Every control that answers a click shows the hand, and a disabled one the arrow: one rule throughout (Sean, 2026-10-18). The web's practice (Material, Bootstrap's reboot, GitHub's Primer) gives the hand to everything clickable where the platforms give it to links alone; what every guide agrees on is consistency, and the site had neither, since Tailwind v4 leaves a button on the browser's arrow while the rows and segments carried `cursor-pointer`. So one base rule in `global.css` gives `button`, `[role=button]`, `[role=tab]`, and `summary` the hand, a link has it from the browser, and a row or label that acts as a control keeps `cursor-pointer` in its recipe (`CURSOR_ROW`, `OPTION_BASE`, the segmented control's target); `:disabled` and `aria-disabled` take `cursor: default`, never `not-allowed`, and the drag handles the grab hand. A smoke test reads every control's computed cursor on every page.

### Copy

- **Sentence case** for every label, button, heading, message, and theme name: "Clear all", "Neo-noir", "Copy value". The only capitals inside a phrase are proper names.
- **Units follow the standards, not the sentence-case rule.** Symbols are case-sensitive and never altered: mL, kB, °F, km/h. Unit names are lowercase, including ones named after people (kelvin, newton), except "Celsius" and "Fahrenheit", which the SI Brochure and NIST write capitalized. Chips and rows show the plural name ("milliliters") next to the symbol.
- **Category names** are single capitalized words as labels: Length, Weight, Volume; a name of two words capitalizes the first alone (Fuel economy).
- **Short and plain.** No exclamation marks, with one approved exception, the feedback form's "Thank you for your feedback!" (Sean, 2026-10-18); no jargon in user-facing text. Error and empty-state text says what to try next.
- **Digit groups never break.** Where text may wrap, digits are grouped with U+202F, the narrow no-break space (the wordmark's lists write `_` for it), and a unit test rejects a plain space between two digits.

## Tuning labs

**Dev pages, and when one is right.** A page under `/dev` ships to the live site, unlinked and asking not to be indexed, so it earns its place only where a Claude artifact (a mock page judged from a picture: the toolbar's row, the SEO plan) cannot do: it needs the real components, tokens, themes, fonts, or measurements, the real engine, or the production origin itself (the owner's switch does: a key in the browser's storage for bigsmall.work, which no other page can set; retired on 2026-10-18 once every device was set and back the next day, since Safari deletes a phone's storage after seven days without a visit). Every dev page has a reason and a retirement condition in the roster below, kept current as pages come and go; the tidy's checklist walks it, and one past its condition retires by `CLAUDE.md`'s recipe, no browsable copy kept (Sean, 2026-10-18: dev pages must not become orphans, and a dev page needs a better reason than an artifact would).

A visual or motion behavior with more than a couple of settings gets a lab page under `/dev`, so the owner tunes it by eye instead of by description: the real component in the page theme, every setting on a slider that shows its shipped value beside a changed one, settings that persist in that browser, and "Copy settings", which prints them as code to paste over the defaults, built from the settings objects' own keys so none is left out (a browser test checks every key). Every version that shipped stays loadable: when tuned settings ship, the ones they replace join the lab's presets under their version name (`src/pages/dev/_wordmark-lab/presets.ts`), so any earlier version can be compared or copied back as the defaults. A lab's controls live beside its page, in a folder named after it (`src/pages/dev/_wordmark-lab/`), use tokens like everything else, and are tools rather than design-system components, so they stay out of the gallery.

`/dev/wordmark-lab` is the first. `/dev/sketchbook-lab` is the second: the sketchbook as the About page shows it, its effect, curve, lengths, frames, glitch strength, Flip's particles, wave, order, and grid on controls, with play without hovering and a preview of reduced motion; under them every sketch, large and at a tab's sizes, each in or out of the rotation, which Copy settings prints too. The labs share their controls (the slider, the panel, the fields' classes) from `src/pages/dev/_lab/controls.tsx`.

A design question with a few answers gets a prototype lab instead, each answer built from the real engine and components with simple state of its own, side by side for the owner to try. ## The sketchbook

The About page's easter egg (docs/UX-SPEC.md §1, "About", since 2026-10-15): the logo sketches, one SVG file each in `apps/web/src/assets/sketchbook/<id>.svg`, named and grouped into families in `features/sketchbook/sketches.ts`. Each is a big thing and a small one on a rounded tile, drawn on a 32-unit grid with the tile's corner at 7 units, like the mark. Round 1 came from the logo canvas (https://claude.ai/artifact/QnNwjo9MzhWEYbzC1vKPmL), R6 among them; rounds 2 and 3 were drawn for the sketchbook (2026-10-15), round 3 adding three to seven families and a Math family on a chalkboard. Each sketch keeps its round in the catalog, and the lab's sheet shows a family's rounds.

- **Artwork, not interface.** Like the brand assets, each sketch keeps colors of its own, which the token guard does not reach and no theme changes: a tile reads as itself on any canvas.
- **Set once, shown by id.** `SketchSprite.astro` puts every file on the page as a symbol, and a tile shows one through `<use>`, so a change swaps a reference and loads nothing.
- **Safe on a page.** A file holds no ids, links, styles, or scripts, which could clash with the page or load something; `test/sketchbook.test.ts` checks every file against those rules and the catalog against the folder. Three sketches (B1, B6, U4) set letters in the system's fonts.
- **On whole pixels, each tile clipping its own change.** The grid's tracks round down to the pixel and the row starts at a whole-pixel inset (`global.css`, "The sketchbook's grid": a third of a width lands between device pixels, and a layer settling there shows it). Each tile clips to its corners (`overflow-clip`, never `hidden`, which would make a scroll container), and lifts the clip, and itself over its neighbors, for a change that reaches past it while it runs (`REACHING_EFFECTS`: Blur's halo, the turns, Flap, and Squash, into the gap alone and never over a neighbor; Glitch stays clipped, its bands having left slivers on an iPhone even with the envelope bringing them back inside, so sliced pieces moved by hand never leave the tile; `data-unclipped` on the tile lifts the clip, set before the change's first frame and left until a clipped change starts on it, since a change of overflow re-rasterizes the picture's edges by up to a hundred levels and a settle must paint nothing new; `data-reach` lifts the tile over its neighbors for the change alone, which costs nothing; docs/LEARNINGS.md, 2026-10-17), which browser tests hold frame by frame: Glitch painting nothing outside, nothing left outside once settled, and the Web Animations ones over no neighbor (Sean, 2026-10-17, settled: the reach gives the tiles dimension); where two pieces meet, the one on top reaches a device pixel past the shared edge (`frames.ts`, `OVER`), since two edges antialiased on the same fractional pixel leave a seam of what lies under; and a layer standing edge-on is hidden, since WebKit draws it as a slab. The sketchbook still bleeds to the page's edge and clips there (`PAGE_BLEED`, beside its grid in `Sketchbook.tsx`), so nothing a change paints can let a phone pan sideways (Sean's iPhone, 2026-10-16 and 17; docs/LEARNINGS.md).
- **Adding one.** Draw it on the tile, add its file and its line in `sketches.ts`, and look at it in the lab's sheet at 88, 32, and 16 px.

## Adding a component

1. Check the inventory. Extend before you add.
2. Create `src/components/<Name>.tsx` (TSX: the React API, run on Preact, ADR 0007) or `<Name>.astro` (static, or driven by the inline script).
3. Style with the utilities above, the recipes, and the patterns in this file. Run `pnpm lint`.
4. Add it to `src/pages/dev/gallery.astro` in its real variants and states.
5. Run `pnpm e2e`. Fix any axe violation before merging.
6. Add a row to the inventory table.
