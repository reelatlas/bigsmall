The browser suite skips a test only on a project it does not apply to: the keyboard walks and mouse-only checks on the phone, and the touch spec (`touch.spec.ts`) and the header's touch check on desktop; seven more skip the phone as "one viewport is enough", a lab's settings and a sketch's change being the same at either (`sketchbook.spec.ts`: every effect landing, the rotation, the reach, loading an earlier version, copying the settings; `wordmark.spec.ts`: the last two), and two whose windows the test sets, the wordmark's phrases and Cooking's box, run on the desktop project alone; so do the header's from-md layout and More's menu (a touch screen scrolls the row instead), while the 16 px check runs on the phone projects alone, the seven clipboard tests skip WebKit, which grants the runner no clipboard permission, and the tag trim skips a browser without `text-box-trim`, saying so. Counts are not kept here, since they change with every feature; `pnpm test` and `pnpm e2e` print them.

## Commands

```bash
pnpm test          # all unit projects, once
pnpm test:watch    # watch mode
pnpm e2e           # Playwright (starts the dev server itself)
pnpm e2e:preview   # the suite against a build on astro preview :4322, when a dev server holds 4321 (pnpm build first)
pnpm lint
pnpm format:check  # or pnpm format to fix
pnpm typecheck
pnpm build
pnpm bundle        # print the gzipped sizes; bundle:check enforces the budget
pnpm check         # lint + format check + typecheck + test + build + bundle check + SEO contract: the gate before every push
```

First-time Playwright setup on a machine, both engines, since the suite's WebKit projects run on every `pnpm e2e`:

```bash
pnpm --filter @bigsmall/web exec playwright install chromium webkit
```

## Golden tests

`packages/core/test/golden/<category>.ts` holds rows of `{ value, from, to, expected, source, tolerance? }`, collected in `golden/index.ts`. Rows are TypeScript so a derived value is written as its defining ratio (`1 / 0.3048`) rather than a hand-rounded decimal. Every row cites where `expected` comes from: a standards document, or "Derived:" plus the exact definition used. The default tolerance is a relative 1e-12; rows that quote a published seven-digit figure (NIST SP 811 Appendix B) use `PUBLISHED_7_DIGITS` (1e-6) so the strict default stays strict everywhere else.

Adding a unit means adding at least one row that exercises it; a test fails when any registered unit has no row. The round-trip test covers every unit automatically at four magnitudes, judged on `max(|expected|, 1)` so tiny temperatures are not failed on floating-point cancellation.

## Registry integrity

`packages/core/test/registry.test.ts` fails on: duplicate or malformed ids, a unit in an unknown category, a category whose base unit is missing or not linear with factor 1, a missing source, fewer than three standard units in a category, a note over 140 characters, a non-positive factor, a change to the category order, and search-key collisions (name, plural, symbol, alias) within a category, and two keys of one unit folding to the same compact key (an inert alias, which search would never reach; 2026-10-18). Collisions across categories are allowed; they are the ambiguity the UI shows with category labels (`oz` today; docs/UX-SPEC.md §3).

## Parser

`packages/core/test/cooking.test.ts` holds Cooking (ADR 0021): every ingredient's id, keys, method, and sources, each once with its figure, and their spread; each figure the rule's from its sources (`cupFigure`: the median, or with fewer than three USDA's measured cups), a liquid's within its density's references; the rule itself (odd and even counts, a half to the even gram, fewer than three); each figure within two of the standard deviations USDA reports for its own cups, where USDA weighed the cup (docs/RESEARCH.md §2.7, the anchor); a cup of each weighing its figure; conversions across volume and weight both ways, and exact within one; reading the ingredient a query ends with; ranking ingredient matches; the units Cooking lists.

`packages/core/test/parse.test.ts` holds the number grammar and the arithmetic. `/` and `-` belong to arithmetic and to unit symbols alike, so each new operator gets a test beside a unit that uses the same character (`5 km/h` is 5 and `km/h`; `5 -ft` is 5 and `-ft`). `packages/core/test/search.test.ts` pins twenty of the catalog's alias and ranking decisions in one sweep, a query and the id it lists first (docs/UNITS-CATALOG.md §5), so an alias that changes a ranking fails there; a second sweep (2026-10-18) pins the four words that name the thing they are (`cooking`, `bytes`, `foot-pound`, `oz.`), each by what it finds and what it no longer does.

## Settings and rounding

`apps/web/test/converter-settings.test.ts` checks Settings (ADR 0018): the sections and their names, the two layers (switches, Other's among them, and single units, presets, Custom, Show custom hidden units), the sections' order, remembered settings read back part by part (Display by what was changed, older versions migrated), a fresh visit's display, and the table and the matches arranged by a rule (shown sections in the cursor's order, the hidden apart, the box's unit always shown). `packages/core/test/rounded.test.ts` checks the rounded formats: places, fractions in the sizes chosen, each in the smallest size chosen, rounding below zero, float noise (forgiven alone: a large value's real digits are kept, a light-year in km to the hundredth, 2026-10-18), and the values left to their digits; and `formatSignificant`, No limit's six significant digits to the nearest, up, or down, below zero too, a value already at its digits left alone, a carry into the next digit and the exponent form where the table takes it, zero as zero, and nothing for what is not finite. The rounded formats are also checked in a decimal-comma locale and in one whose minus is U+2212 (the sign read from Intl, never written), on an invalid locale (the fallback, never a throw), at and past 1e15 (places give way to the significant digits), and at the edges of what a double holds.

## Theme contract

`test/themes.test.ts` parses each theme CSS file and checks the token contract and the contrast pairs from `src/lib/themes.ts`. A failing pair prints both colors and the achieved ratio.

## CI

`.github/workflows/ci.yml` starts only when someone runs it (Actions → Run workflow, or `gh workflow run CI`). A push does not start it, and Vercel does not wait for it (Sean, 2026-10-18; docs/DEPLOYMENT.md).

- **verify**: install, lint, format check, typecheck, unit tests, build, bundle budget, SEO contract. `pnpm check` runs the same steps locally, and that is the check to run before a push.
- **e2e**: install Chromium and WebKit, run Playwright. The HTML report is uploaded on failure. Locally this is `pnpm e2e`, for a change to behavior.

Both jobs run on a named image (`ubuntu-26.04`) with every action on its newest major. The comment above the jobs lists the pins and why; review them with the rest at each milestone (ADR 0005).
